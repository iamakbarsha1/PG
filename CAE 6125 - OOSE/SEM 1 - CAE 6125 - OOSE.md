### 1. OOSE:

- OOSE stands for Object-Oriented Software Engineering. 
- It is a methodology or approach used for designing, analyzing, and developing software systems using object-oriented concepts and techniques. 
- OOSE emphasizes the use of objects, classes, inheritance, encapsulation, and polymorphism to model real-world entities and their interactions in software systems. 
- It involves several stages such as requirements analysis, system design, implementation, testing, and maintenance, all of which are carried out while adhering to object-oriented principles and practices.

### 5. Data Abstraction:

- The process of hiding the implementation details of data and revealing only the essential features or properties to the user.
- It allows users to interact with data at a higher level of abstraction, focusing on what the data represents rather than how it is stored or manipulated internally.

### 12. Stages in project scheduling:

1. Planning: 
	1. Defining project scope, objectives, and deliverables, and creating a detailed project schedule.
2. Sequencing: 
	1. Determining the order in which project activities should be performed based on dependencies and constraints.
3. Resource allocation: 
	1. Assigning resources such as manpower, equipment, and materials to project tasks according to availability and requirements.
4. Estimating time and costs: 
	1. Estimating the duration and costs associated with each project activity.
5. Developing the schedule: 
	1. Creating a comprehensive project schedule that outlines start and end dates for each task, milestones, and deadlines.
6. Monitoring and controlling: 
	1. Tracking project progress, identifying deviations from the schedule, and implementing corrective actions as needed to ensure project objectives are met.
7. Closing: 
	1. Completing all project activities, reviewing project performance, and documenting lessons learned for future projects.

### 13. Different concepts of object oriented design paradigm:

1. Abstraction: 
	1. The process of simplifying complex systems by focusing on the essential properties and hiding unnecessary details.
2. Encapsulation: 
	1. Bundling data and methods together within a class and restricting access to the internal state of an object to ensure data integrity and security.
3. Inheritance: 
	1. The ability of a class to inherit properties and behavior from another class, allowing for code reuse and creating hierarchical relationships.
4. Polymorphism: 
	1. The ability of objects to take on different forms or behaviors depending on the context, allowing for flexibility and extensibility in software design.
5. Modularity: 
	1. Breaking down a system into smaller, self-contained units (modules) with well-defined interfaces, promoting code reusability, maintainability, and scalability.
6. Composition: 
	1. Building complex objects by combining simpler objects or components, enabling flexibility in design and promoting code reuse.
7. Association: 
	1. Establishing relationships between objects to model real-world interactions and dependencies, facilitating communication and collaboration between objects.
8. Dependency injection: 
	1. Passing dependencies to objects externally rather than creating them internally, promoting loose coupling and enhancing testability and maintainability.
9. Interfaces: 
	1. Defining contracts that specify a set of methods that classes implementing the interface must adhere to, enabling polymorphism and providing a common interface for disparate objects.

### 14. Types of software testing:

1. Unit Testing: 
	1. Testing individual components or modules of software in isolation to ensure they function correctly.
2. Integration Testing: 
	1. Testing the interactions and interfaces between integrated components to verify that they work together as expected.
3. System Testing: 
	1. Testing the entire software system as a whole to verify that it meets specified requirements and behaves as intended in various scenarios.
4. Acceptance Testing: 
	1. Testing conducted to determine whether a software system meets acceptance criteria and is ready for deployment.
5. Regression Testing: 
	1. Testing performed to ensure that changes or enhancements to a software system have not adversely affected existing functionality.
6. Performance Testing: 
	1. Testing conducted to evaluate the performance characteristics of a software system, such as responsiveness, scalability, and stability, under various load conditions.
7. Security Testing: 
	1. Testing conducted to identify vulnerabilities and weaknesses in a software system's security mechanisms and controls.
8. Usability Testing: 
	1. Testing conducted to evaluate the user-friendliness and ease of use of a software system from an end-user perspective.
9. Compatibility Testing: 
	1. Testing conducted to ensure that a software system functions correctly across different hardware, operating systems, browsers, and network environments.
10. Exploratory Testing: 
	1. Ad-hoc testing performed without predefined test cases to discover defects and issues through exploration and experimentation.
11. Smoke Testing: 
	1. Testing conducted to verify that critical functionalities of a software system work properly before proceeding with more comprehensive testing.
12. Localization Testing: 
	1. Testing conducted to ensure that a software system is properly adapted to meet the linguistic, cultural, and regulatory requirements of specific target markets or locales.
